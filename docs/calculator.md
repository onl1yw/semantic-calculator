# Вычисления и личные определения

[← Semantic Calculator](../README.md)

## Ввод

Введите слово или выражение, например `король − мужчина + женщина`, и нажмите
Enter или `=`. Подсказки дополняют последнее слово. Для отдельного операнда
можно выбрать слово с клавиатуры калькулятора.

Цепочка считается последовательно, слева направо. Скобки не поддерживаются.
Кроме `−`, `×`, `÷` доступны символы `-`, `*`, `/` и завершающий `=`.
Для вычитания обычным дефисом нужны пробелы: `король - мужчина`. Дефис внутри
слова сохраняется. Начальный `−мужчина` означает самостоятельное отрицание.
Ввод `+ женщина` продолжает текущий результат, а `королева +` выбирает слово
и включает сложение с ожиданием следующего операнда.

Максимальная длина выражения — 1024 символа, слова — 64. Неизвестное слово
показывается с ошибкой; предыдущие операнды, память и история сохраняются.

## Арифметика

Векторы слов нормализованы для равного веса операндов. Для векторов `a` и `b`:

| Операция | Компонента результата |
| --- | --- |
| `+` | `a[i] + b[i]` |
| `−` | `a[i] − b[i]` |
| `×` | `a[i] * b[i]` |
| `÷` | `a[i] / b[i]` |
| `+/−` | `−a[i]` |

Нулевая компонента делителя вызывает ошибку. Нулевой или нечисловой результат
сохраняет предыдущее корректное состояние, поскольку у него нет направления
для поиска ближайшего слова.

Полный результат хранится без повторной нормализации. Для поиска нормализуется
его копия. Это сохраняет вес накопленных операндов при продолжении цепочки.
Показанное слово служит подписью результата.

До 128 разных исходных слов в цепочке исключаются из кандидатов поиска.
Их список сохраняется вместе с результатом, историей и памятью. Новый ручной
ввод начинает список источников с выбранного слова. При продолжении вычисления
и `M+` источники операндов объединяются.

## Память

- `M+` добавляет полный вектор текущего результата в память.
- `MR` возвращает вектор памяти как текущий операнд.
- `MC` очищает память.

Первый `M+` сохраняет подпись результата; последующие находят ближайшее слово
для накопленной суммы. Нулевая сумма подписывается `0`.

```text
A + B = C       # результат r = v(A) + v(B), подпись C
M+              # память m = r
MR + D = E      # результат v(A) + v(B) + v(D)
```

## RE: личные слова и ответы

`RE` открывает форму REDEFINE с двумя режимами:

- **Назвать результат:** вычислить `ум + красота` и сохранить слово `миша`.
  Оно получает полный вектор суммы. Ввод `миша − красота` использует этот вектор.
- **Задать ответ:** вычислить `−мужчина` и задать ответ `женщина`. При повторении
  выражения используется вектор женщины; с ним можно продолжить вычисление.

Личные слова участвуют во вводе, подсказках и поиске ближайшего результата.
При совпадении имени с базовым словом личное значение имеет приоритет.
Источником личного слова становится его имя, чтобы работало обратное вычитание
компонентов определения.

Правила сопоставляются по выражению с нормализацией регистра, пробелов и знаков.
Другой порядок слов требует отдельного правила. Заданный ответ сохраняет
словарное значение слова, на которое ссылается правило.

В «Моём словаре» можно редактировать имя и выражение слова, выражение и ответ
правила, возвращать слово в калькулятор и удалять определения. Переименование
обновляет ссылающиеся правила. Удаление слова удаляет связанные правила;
последнее удаление можно отменить до нового изменения или перезагрузки.
Лимит — 100 личных слов и 100 правил.

## Сохранения

`localStorage` сохраняет текущий вектор, память, ввод и последние 50 записей
истории в `semantic-calculator:state:v1`. Структура включает версию схемы,
модель и её ревизию. При восстановлении проверяются размерность и конечность
чисел; сохранения предыдущих форматов проходят миграцию.

Личные определения хранятся отдельно:
`semantic-calculator:definitions:v1:<model_id>:<model_revision>`.
После смены модели старый личный словарь остаётся в ключе прежней ревизии.

При недоступном хранилище калькулятор продолжает работать в памяти вкладки
и сообщает, что сохранение недоступно. Личные определения при неудачном
сохранении сохраняют прежнее состояние. Между устройствами данные не синхронизируются.

## Словарный API

| Запрос | Назначение |
| --- | --- |
| `GET /api/health` | Готовность, модель и ревизия |
| `GET /api/words?prefix=...` | До 10 подсказок, префикс от двух символов |
| `GET /api/words/{word}/vector` | Нормированный вектор и ревизия |
| `POST /api/nearest` | Ближайшее слово для 300 чисел с `exclude_words` |

Браузер выполняет арифметику и передаёт в API нормированную копию результата
для поиска. Backend не записывает выражения, историю, память или личные
определения; access log отключён. Переданные векторы не сохраняются.
Запрос с другой ревизией модели отклоняется.

Размер тела ограничен 16 КиБ. Поиск, запросы и соединения имеют ограниченную
параллельность и таймауты; при перегрузке возвращаются `429` или `503` с
`Retry-After`. Облачные лимиты приведены в [инструкции развёртывания](deployment.md).
