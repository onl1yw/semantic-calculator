# Работа с проектом

## Ветки и pull request

Изменения готовятся в отдельной ветке и попадают в `main` через pull request.
Защита `main` требует успешного CI `checks` и актуального состояния относительно
основной ветки. Обсуждения PR должны быть разрешены перед слиянием.
Force-push и удаление `main` запрещены; правила действуют и для администраторов.

## Размер и ответственность файлов

Ориентир для растущего файла — 300–500 строк. Это мягкая граница для пересмотра
структуры, а не обязательный размер или запрет на исключения. Небольшой законченный
компонент может занимать гораздо меньше строк.

Разделяем код по ответственности: интерфейс, управление состоянием, вычисления,
хранение данных. Новая граница должна упрощать чтение и изменение кода.
Не сокращаем строки уплотнением кода и не создаём обёртки ради счётчика строк.

## Структура

| Каталог или модуль | Ответственность |
| --- | --- |
| `frontend/src/App.tsx` | Сборка экрана и связь компонентов |
| `frontend/src/components/` | Экран, клавиатура, память, история и формы RE |
| `frontend/src/hooks/` | Состояние калькулятора, личные определения и подсказки |
| `frontend/src/calculator.ts`, `math.ts` | Последовательные действия и векторная арифметика |
| `frontend/src/definitions.ts`, `storage.ts` | Личные определения и совместимость сохранений |
| `frontend/src/api.ts` | Доступ к словарному API и ограниченный кеш |
| `frontend/src/styles/` | Базовые стили и стили по частям интерфейса |
| `assets/` | Публичные ресурсы: favicon и карточка для превью ссылок |
| `backend/` | API, ограничения нагрузки и локальный словарь |
| `scripts/` | Подготовка модели, проверка секретов, запуск и деплой |
| `infra/yandex/` | Аккаунты, registry и ограничения шлюза |

Компоненты получают данные и действия через типизированные свойства. Векторная
арифметика и правила личного словаря остаются в обычных TypeScript-модулях.
Хуки связывают эти модули с жизненным циклом React и состоянием браузера.

## Что сохранять при изменениях

- Полный накопленный вектор результата и памяти; показанное слово — его подпись.
- Совместимость сохранений и разделение данных по ревизии модели.
- Локальное хранение истории и личных определений в браузере.
- Ограничения API, таймауты и отсутствие записи пользовательских векторов.
- Фокус ввода с клавиатуры и на мобильных устройствах, подсказки и навигацию по вкладкам.

Модели, базы, выгрузки и секреты исключены из Git. Для проверки вычислений
используются маленькие тестовые словари, поэтому тесты не требуют скачивания модели.

## Проверка изменений

```bash
.venv/bin/python -m pytest -q
npm test --prefix frontend
npm run build --prefix frontend
git diff --check
.venv/bin/python scripts/security_scan.py
.venv/bin/python scripts/terraform_yandex.py validate
```

После переноса компонентов проверяем затронутые сценарии в браузере: ввод
выражения, память и восстановление страницы, история, создание и редактирование
определений. При переносе стилей сравниваем экран на широком и мобильном экранах.
