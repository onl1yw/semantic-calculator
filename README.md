# Semantic Calculator

Семантический калькулятор для русских слов: интерфейс в духе калькулятора iPhone,
арифметика над векторами, ближайшее слово на экране.

Локальное приложение реализовано: React/TypeScript в браузере, тонкий FastAPI,
локальный словарь и точный поиск ближайшего слова. Вычисления, память и история
сохраняются в браузере. Подключение к YDB и работа с Яндексом относятся к будущему
этапу; облачные ресурсы не создавались и данные в облако не загружались.

## Запуск

Нужны Python 3.12+ и Node.js 22.12+. Проверено на Python 3.14 и Node.js 22.22.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
npm ci --prefix frontend
.venv/bin/python scripts/prepare_model.py
npm run build --prefix frontend
bash scripts/dev.sh
```

Открыть [http://127.0.0.1:8000](http://127.0.0.1:8000). Первая подготовка скачивает
официальный архив размером около 638 МБ. Готовые данные занимают ещё около
0.25 ГБ для существительных. При повторной подготовке используются уже скачанный архив и валидный
словарь; их SHA-256 проверяются.

После изменения frontend повторить `npm run build --prefix frontend`.
Для разработки с обновлением страницы без пересборки можно параллельно
запустить `npm run dev --prefix frontend` и открыть порт 5173: Vite направляет
запросы `/api` на локальный backend, порт 8000.

```bash
.venv/bin/python -m pytest -q
npm test --prefix frontend
```

Зависимости зафиксированы в `requirements.lock.txt` и `frontend/package-lock.json`.

Структура кода, соглашения и проверки описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

## Модель и локальные данные

Для локального эксперимента используем **RusVectōrēs
`ruwikiruscorpora_upos_skipgram_300_2_2019`** — Word2Vec Skipgram на НКРЯ
и русской Википедии за декабрь 2018 года.
В [каталоге моделей RusVectōrēs](https://rusvectores.org/ru/models/) указаны
248 978 записей, размерность 300 и точность 0.72 на русской версии семантических
секций Google Analogies. Это опубликованная оценка, а не результат тестов приложения.
Она относится к полной модели до нашего ограничения на существительные.
Из полного словаря оставляем только 57 568 токенов с тегом `NOUN`.
Базовые подсказки, ввод и поиск результатов используют только этот набор.
Пользовательские определения дополняют его локально в браузере.
В исходных данных постфикс сохранён (`король_NOUN`), а в интерфейсе скрыт:
пользователь вводит и видит `король`. Токены `PROPN` и других частей речи
в этот эксперимент не включены.
Каталог указывает CC-BY как лицензию моделей; при использовании сохраняем
атрибуцию и проверяем сопроводительные сведения скачанного архива.

Локально подготовлено соответствие `слово -> вектор` и обратный поиск ближайшего
слова по косинусной близости. Обратное соответствие не является точной обратной
функцией: результат арифметики обычно не совпадает с вектором словарного слова.

Исходные векторы сохраняем, а для поиска готовим L2-нормированную матрицу.
Модель, словарь, таблица и производные файлы хранятся только в игнорируемых
каталогах `models/` и `data/`. Они не входят в публичный репозиторий.
`scripts/prepare_model.py` создаёт:

- `dictionary.sqlite3`: 57 568 строк `word`, `row_index`, `vector`; исходный
  вектор хранится как 300 little-endian Float32 чисел в BLOB.
- `raw_vectors.npy`: исходная матрица без изменения значений.
- `vectors.npy`: L2-нормированная матрица для поиска и выдачи операндов.
- `words.json`: словарь в том же порядке, что строки обеих матриц.
- `manifest.json`: источник, ревизия, размерность, количество и SHA-256 файлов.
- `source-meta.json`, `source-README.txt`: оригинальная атрибуция из архива.

Матрица и словарь считываются из `model.bin` в стандартном бинарном формате
Word2Vec, без загрузки кода или весов обучения. Новые данные хранятся в
`data/dictionary-word2vec-nouns` и используются по умолчанию. Фильтрация части
речи включена в ревизию данных, чтобы не смешивать состояние разных вариантов.

Предыдущая GeoWAC сохранена отдельно в `data/dictionary`. Вернуться к ней можно
при следующем запуске:

```bash
SC_DATA_DIR=./data/dictionary bash scripts/dev.sh
```

Её импортёр также сохранён: `.venv/bin/python scripts/prepare_model.py
--model geowac_lemmas_none_fasttextskipgram_300_5_2020`. Он считывает только две
разрешённые структуры данных Gensim 3.8, без загрузки матрицы субслов fastText.

Для будущего переноса можно сформировать локальный JSONL-экспорт нормированных
векторов. Команда ничего не загружает в Яндекс:

```bash
.venv/bin/python scripts/export_dictionary.py
```

Результат — игнорируемый Git файл `data/dictionary-export.jsonl.gz`.

## Контракт вычислений

За одно действие выполняется одна бинарная операция. Цепочка считается
последовательно, как на обычном калькуляторе: результат можно использовать
как левый операнд следующей операции. Парсер сложных выражений не требуется.
Арифметику и нормализацию для поиска выполняет браузер.

Для двух векторов `a` и `b` операции выполняются покомпонентно:

| Кнопка | Компонента результата |
| --- | --- |
| `+` | `a[i] + b[i]` |
| `−` | `a[i] − b[i]` |
| `×` | `a[i] * b[i]` |
| `÷` | `a[i] / b[i]` |

Покомпонентное деление возвращает явную ошибку, если делитель содержит нулевую
компоненту, без подмены нуля. Кнопка `+/−` меняет знак всех компонентов.

Векторы слов один раз нормализованы для равного веса операндов.
Полученный арифметический результат сохраняется целиком, без повторной
нормализации или замены вектором показанного слова. Для каждого поиска
нормализуем только его копию и выбираем ближайшее слово. Иначе повторная
нормализация после каждого действия изменит вес накопленного результата
и нарушит эквивалентность последовательного сложения.

Нулевой или нечисловой результат не имеет корректного направления для поиска;
в этом случае показываем понятную ошибку и сохраняем предыдущее корректное
состояние. Неизвестное слово тоже требует явной ошибки. Для первого этапа
выбираем слова из словаря с подсказками по мере ввода.

`король − мужчина + женщина ≈ королева` — пример желаемого взаимодействия.
Предыдущая GeoWAC при поиске по всему словарю вернула **«король»**
(косинусная близость 0.8723); «королева» занимает третье место (0.6808).
В калькуляторе исходные слова исключаются из кандидатов после вычисления:
для этого примера результат GeoWAC — **«правитель»** (0.6899), затем идёт
«королева» (0.6808). Это изменение выбора отображаемого слова; полный вектор
результата остаётся прежним.

В активном эксперименте Word2Vec с фильтром `NOUN` это выражение возвращает
**«королева»** (0.7523). На 342 семейных аналогиях из официального набора,
доступных обеим моделям, точный первый ответ получен в 244 случаях (71.3%)
против 232 (67.8%) у прежней GeoWAC. Это сравнение модели вместе с фильтром
кандидатов, а не изолированная оценка архитектуры. Общая семантическая оценка
и бытовые суммы этим тестом не покрываются.

Список исходных слов сохраняется с операндом, историей и памятью. При продолжении
цепочки объединяем источники обоих операндов, при M+ — источники всех добавленных
векторов. MR сохраняет эти исключения. Новый ручной ввод слова начинает новый
список источников. Поддерживается до 128 разных исходных слов в одной цепочке.
Для старых результатов восстанавливаем источники из сохранённого выражения;
для старой памяти — при совпадении её вектора с текущим результатом или историей.

## Экран и память

Тёмный экран, крупное слово результата, круглые кнопки действий и оранжевые
операторы в духе калькулятора iPhone. Вместо набора цифр — ввод слова и подсказки
из локального словаря. На экране отображается слово, внутри хранится вектор.
Страница содержит только калькулятор: без обрамления телефона, рекламных
блоков и служебных подписей. История открывается по кнопке, сообщения об ошибках
появляются только при необходимости.

Ввод принимает слово или выражение: `король − мужчина + женщина` считается по
Enter или кнопке `=`. `королева +` по Enter выбирает слово и включает сложение;
поле остаётся открытым для следующего слова. Можно продолжить результат вводом
`+ женщина`. Начальный `−мужчина` или `-мужчина` считается как самостоятельное
отрицание вектора, даже если уже есть результат. Полная цепочка, начинающаяся со слова, начинает самостоятельный
расчёт, если в ней несколько слов. Операции идут слева направо, как при нажатии
кнопок. Поддерживаются также `-`, `*`, `/` и завершающий `=`; дефис внутри слова
сохраняется, для вычитания обычным `-` нужны пробелы. Скобки не поддерживаются.
Подсказки дополняют последнее слово выражения. Если подтверждённого слова нет
в словаре, показываем `ERROR` и само слово с пояснением; ввод можно исправить,
а предыдущие операнды, память и история сохраняются. Выражение ограничено
1024 символами, отдельное слово — 64.

Кнопки памяти:

- `M+` добавляет текущий полный вектор в память; пустая память начинается с нуля.
- `MR` возвращает полный вектор из памяти как текущий операнд.
- `MC` очищает память.

Рядом с кнопками показано содержимое памяти (`КОРОЛЕВА`) или «Память пуста».
Первый M+ сохраняет подпись текущего результата; последующие M+ находят ближайшее
слово для суммы векторов. MR возвращает сохранённую подпись и полный вектор.
Нулевая сумма подписывается `0`, для её вызова нужно сначала добавить слово.
Старые сохранения остаются совместимыми: подпись восстанавливается из известного
вектора текущего результата/истории или поиском по словарю.

## Личные определения: RE

Кнопка `RE` открывает короткую форму REDEFINE. «Мой словарь» находится в отдельной
вкладке рядом с историей вычислений. Пустой экран показывает серое
«ноль», кнопка удаления символа заменена на RE; редактирование ввода доступно
через обычную клавиатуру.

- **Назвать результат:** посчитать `ум + красота`, нажать RE и сохранить имя
  `миша`. Слово получает полный вектор суммы с исходной длиной. Ручной ввод
  `миша − красота` использует этот вектор и может вернуть `ум`.
- **Задать ответ:** посчитать `−мужчина`, нажать RE и указать `женщина`.
  При повторении этого выражения используется вектор женщины, с которым
  можно продолжать вычисления. Правило также применяется к кнопке смены знака
  на слове «мужчина». Оно не переписывает словарное значение женщины.

Личные слова участвуют во вводе, подсказках и поиске ближайшего результата.
Если имя совпадает с базовым словом, личное значение имеет приоритет и старый
базовый вектор с этим именем исключается из результатов. При вводе своего слова
список источников начинается с его имени; компоненты определения не исключаются
автоматически, чтобы работало обратное вычитание. Правила сопоставляются по
выражению с нормализацией регистра, пробелов и знаков. Похожая арифметическая
формула с другим порядком слов требует своего правила.

В «Моём словаре» нажатие на запись открывает редактирование: у слова можно
изменить имя и выражение, у правила — выражение и ответ. Изменение формулы слова
пересчитывает его вектор; переименование обновляет ответы правил, ссылающиеся
на это слово.
Стрелка возвращает слово в калькулятор. Также можно удалить определение.
Новое сохранение с тем же именем/выражением заменяет
его значение. Удаление слова также удаляет правила, использующие это имя;
последнее удаление можно отменить до нового изменения или перезагрузки.
Поддерживается до 100 личных слов и 100 правил.

Определения хранятся в отдельном ключе `localStorage`
`semantic-calculator:definitions:v1:<model_id>:<model_revision>`; у каждой
версии модели собственный словарь. Старые определения сохраняются в своём ключе
при смене модели. Backend и файлы модели не изменяются. Серверный поиск получает
вектор результата, локальные кандидаты сравниваются с его ответом в браузере.
При недоступном хранилище сохранение показывает ошибку и сохраняет прежние
определения.

Пример при пустой памяти:

```text
A + B = C       # внутри r = v(A) + v(B), на экране ближайшее слово C
M+              # память m = r
MR + D = E      # внутри v(A) + v(B) + v(D), на экране ближайшее слово E
```

Здесь `v(C)` никогда не подставляется вместо `r`. Если вручную заново ввести
слово `C`, это будет самостоятельный словарный вектор `v(C)`.

## Браузер и localStorage

Браузер отвечает за операнды, арифметику, последовательные действия, кнопки
памяти и историю. В `localStorage` под ключом `semantic-calculator:state:v1`
сохраняем текущий полный вектор, вектор памяти, показанное слово, состояние
ввода, подпись памяти и последние 50 записей истории. Состояние включает версию схемы,
идентификатор и ревизию модели, чтобы при восстановлении не смешивать векторы
разных моделей. Вектор памяти сохраняется с исходной длиной, как и текущий
накопленный результат.

После перезагрузки восстанавливаем состояние, проверив структуру, размерность
и конечность чисел. При недоступном хранилище или превышении его квоты
калькулятор продолжает работать в памяти вкладки и сообщает, что сохранение
недоступно. Очистка истории затрагивает только ключи приложения.
Полный словарь в `localStorage` не загружаем; уже полученные векторы слов
можно держать в небольшом ограниченном кеше браузера.

Сохранение между сессиями и условия доступности описаны в
[документации localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

## Тонкий backend

Backend предоставляет доступ на чтение к словарю и ограничивает нагрузку на
хранилище. Он работает без пользовательских сессий:

| Запрос | Назначение |
| --- | --- |
| `GET /api/health` | Готовность словаря, модель и ревизия |
| `GET /api/words?prefix=...` | Подсказки из словаря, до 10 слов |
| `GET /api/words/{word}/vector` | Нормированный вектор слова, идентификатор и ревизия модели |
| `POST /api/nearest` | Ближайшее слово и косинусная близость для одного вектора из 300 чисел, с необязательным списком `exclude_words` |

Для поиска браузер отправляет нормированную копию результата, ревизию модели
и до 128 исходных слов для исключения из кандидатов.
Это временная передача 300 чисел для поиска по словарю. Backend не записывает
этот вектор, список исключений, выражение, историю или память пользователя в базу, кеш результатов
или журналы; тело запроса не логируется. Скрипт запуска отключает access log
и доверие к заголовкам с IP. Полный результат вычисления и память остаются
в браузере.

Арифметического endpoint, сохранения истории и серверных кнопок памяти нет.
Ревизия модели в запросе проверяется: векторы от другой ревизии отклоняются.
Локально поиск реализует адаптер к матрице в `data/`; будущий адаптер YDB
должен поддерживать тот же контракт чтения и поиска. Конкретный механизм
поиска в YDB выбирается на будущем этапе.

## Ограничения нагрузки

До обращения к хранилищу проверяем размер тела запроса, длину и формат слова,
размерность вектора, конечность чисел и ненулевую норму. `/api/nearest`
принимает один вектор и возвращает один результат. Подсказки требуют префикс
из хотя бы двух символов; длина слова или префикса ограничена 64 символами,
размер тела запроса — 16 КиБ.

Реализованы token bucket лимиты на IP и на процесс, отдельные бюджеты поиска,
ограничение одновременных поисков, таймаут получения тела и таймаут поиска,
ответы `429`/`503` с `Retry-After`. Учёт клиентов ограничен 2048 IP с удалением
просроченных записей. При таймауте поиск удерживает занятую позицию до окончания
работы, чтобы повторные запросы не создавали бесконечную очередь.

| Ограничение по умолчанию | Значение |
| --- | --- |
| Запросы на IP | 120/мин, burst 20 |
| Поиски на IP | 60/мин, burst 8 |
| Запросы на процесс | 1200/мин, burst 40 |
| Поиски на процесс | 240/мин, burst 4 |
| Одновременные поиски | 2, без очереди |
| Получение тела / поиск | 5 с / 2 с |
| Соединения Uvicorn / backlog | 64 / 64 |
| Серверный кеш словарных векторов | 256 слов |

Точный поиск выполняется по read-only memory map нормированной матрицы.
На GeoWAC медиана десяти прогретых поисков на текущем Mac составила около 1.34 мс;
первое чтение заняло около 192 мс. Это локальный замер, не облачный SLA.
Настройки читаются из переменных `SC_*`; пример — `.env.example`.
Скрипт запуска использует один процесс. При публичном запуске с несколькими
экземплярами общий бюджет нужно обеспечивать на входе в сервис.

Для публичного запуска нужна внешняя защита от сетевого DDoS перед backend.
Лимиты приложения защищают его ресурсы, но сами по себе не устраняют
перегрузку канала. Разделение этих мер описано в
[OWASP Denial of Service Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html).
На текущем этапе это контракт будущего запуска: облачные и внешние сервисы
не подключаем. Будущие реквизиты доступа к базе хранятся на сервере, браузер
общается с API.

## Состояние работы

- Готовы локальная таблица и нормированная матрица выбранной модели.
- Готов тонкий backend с ограничениями нагрузки и без записи пользовательского состояния.
- Готов интерфейс с арифметикой, памятью, историей и восстановлением localStorage.
- Перенос в YDB и публичный запуск относятся к отдельному будущему этапу.
